# The mstack guide

mstack applies poteto's pstack method to design work. It routes a design task to a playbook, copies the playbook's steps into the todo list, grounds each decision in a named principle, and proves the work on the rendered artifact. This guide walks through it in the order you will use it.

1. [Set up mstack](01-setup.md)
2. [Route work through `/design-mode`](02-design-mode.md)
3. [Discover and investigate before you design](03-discover-and-investigate.md)
4. [Design and prototype](04-design-and-prototype.md)
5. [Evaluate a design](05-evaluate.md)
6. [Hand off, check the build, and measure](06-handoff-qa-measure.md)
7. [Run long work and come back to it](07-long-runs.md)
8. [Principles and evidence tiers](08-principles-and-evidence.md)
9. [Make it yours](09-make-it-yours.md)
10. [Recipes and pitfalls](10-recipes-and-pitfalls.md)

The skills and playbooks own the rules. When this guide and a skill file disagree, the skill file wins. Each page names the files it summarizes.

For a quick answer instead of the full guide, type `/mstack:design-help` with your question.
