### Design sprint

**You own the sprint question and the run. The human decider owns the pick. Real users own the verdict.**

A time-boxed sprint-lite adapted from the GV Design Sprint, a five-day process that ends with customer tests of a realistic prototype. Read GV's own material for the method. This playbook keeps only the agent's part.

1. Set the stage. Write the one critical question the sprint must answer, name the human decider, and fix the deadline. No decider means no sprint.
2. Map and target (**principle-frame-the-problem**). Start from the long-term goal and map the challenge. Use tier 2 evidence and the user's own expertise as the expert input, never invented experts. Pick one target moment on the map.
3. Sketch independently and in parallel through the **diverge** skill (**principle-diverge-then-converge**). Its Phase B owns the fan-out, so spawn no sketch agents yourself. Ask it for sketches with no shared context, on mixed models (opus, sonnet) when available, so they stay independent.
4. Decide. Run the **critique** skill over the sketches against the sprint question. Pick one on that evidence as a labeled default, and record the decider's pick as an open decision with the evidence pack (**principle-propose-and-proceed**). Turn the pick into a storyboard the test will walk. If the decider later picks differently, redo the storyboard and steps 5 to 7 on their pick.
5. Prototype the storyboard with **Prototype** (playbooks/prototype.md). Build a realistic front surface with nothing real underneath, and only the screens the storyboard needs.
6. Prepare the test day as a ready-to-run interview kit for a human facilitator. It holds the plan, a recruiting screener, consent, the facilitator script, tasks drawn from the storyboard, an observer sheet, and a synthesis template. Write each task with a clear, realistic goal that does not hint at the answer. Use design:user-research if installed, else **Usability test** (playbooks/usability-test.md). Link Krug's free test kit as a model. Never copy or repost it.
7. Never simulate the interviews, the participants, or their reactions (**principle-never-fabricate-user-evidence**). Record the test as a pending gate. Meanwhile run tier 1 inspection on the prototype and label it as hypothesis.
8. When the human returns notes or recordings, synthesize them with design:research-synthesis if installed, else per **Usability test**. Answer the sprint question from that evidence. Hand the surviving direction to **Feature design** (playbooks/feature-design.md).

**Reply:** the sprint question, the decider, the target, the sketches, your default pick, the decider's pick as an open decision, the storyboard, the prototype path, the kit path, and the pending test gate. After synthesis, the answer to the sprint question with its evidence.

**Grounded in:** [GV Design Sprint](https://www.gv.com/sprint/), [Sprint (Knapp, Zeratsky, Kowitz 2016)](https://www.thesprintbook.com/) for the Decider role, [Krug's usability test downloads](https://sensible.com/download-files/), [GOV.UK user research](https://www.gov.uk/service-manual/user-research).
